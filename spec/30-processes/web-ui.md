# LAN web UI

serves:
  - ../20-stories/scheduling.md
  - ../20-stories/connectivity.md
  - ../20-stories/feeding.md

## Purpose

When Wi-Fi STA has a routable IP, the device may serve a minimal HTTP control
panel on port 80 so the user can view today's schedule, edit the weekly
schedule, dispense manually, change feed mode, and set timezone — without a
MQTT broker or Home Assistant. `[design]`

No HTTP authentication or TLS in v0 — LAN access only, same threat model as
the open provisioning AP. `[design]`

## Compile-time gate

| Flag | Default (bring-up) | Meaning |
|------|-------------------|---------|
| `WEB_UI_ENABLE` | `y` in `feature.mk` | Admin UI on STA; set `n` before production release |

## Lifecycle

| Phase | HTTP server role |
|-------|------------------|
| AP provisioning (no stored Wi-Fi) | Captive portal only — see [provisioning-flow.md](provisioning-flow.md) |
| STA ready (`EVT_WIFI_STA_READY`) | Start admin UI on port 80 when `WEB_UI_ENABLE=y` and heap preflight passes |
| OTA download preflight | Stop admin HTTP (same window as [remote telnet](uart-console.md) suspend) |
| OTA failure resume | Restart admin HTTP when STA still ready |

Only one httpd role at a time: provisioning portal **or** admin UI, never both.

### Heap preflight

Before `http_server_port.start(80)` on STA, require
`xPortGetFreeHeapSize() >= WEB_UI_MIN_HEAP` (`[tune]` 24576 bytes). On failure
log `web ui skipped (low heap)` once per boot and do not start the admin UI.

## Static UI

| Method | Path | Response |
|--------|------|----------|
| GET | `/` | Pre-gzipped single-page HTML (`Content-Type: text/html; charset=utf-8`, `Content-Encoding: gzip`, `Cache-Control: no-cache`) |

Assets are built on the host (`tools/web/build.sh`) into
`firmware/src/web_ui_gz.c` (gitignored, regenerated by `build-firmware.sh` and
host tests). Client logic and tests: [web-ui-client.md](web-ui-client.md).
Target compressed size `[tune]` ≤ 14 KB.

## HTTP API

All `/api/*` routes return `Content-Type: application/json`. Mutation responses
use `{"ok":true}` or `{"ok":false,"error":"<reason>"}`. Every failed POST
logs `[web] <path> rejected (<reason>)` (readable at `GET /api/log`).

Read payloads match retained MQTT state / command wire formats in
[mqtt-protocol.md](mqtt-protocol.md) unless noted.

### Reads

| Method | Path | Body |
|--------|------|------|
| GET | `/api/schedule/state` | Same JSON as `.../schedule/state` |
| GET | `/api/schedule/next` | Same JSON as `.../schedule/next` |
| GET | `/api/config` | Same JSON as `.../config` |
| GET | `/api/feed/mode` | Plain text `open_loop` or `compensated` (same as `.../feed/mode`) |
| GET | `/api/feed/overfill` | JSON `{"enabled":false,"threshold_g":50}` (same as `.../feed/overfill`) |

| GET | `/api/export` | Settings backup JSON — see [Administration](#administration) |

#### Status composite

v0 exposes **one** status GET. The UI polls `/api/status` only (no per-topic mirror
routes). Field values use the same wire formats as retained MQTT topics in
[mqtt-protocol.md](mqtt-protocol.md). Telemetry strings are formatted from each
publisher module's last-known cache (`mqtt_*_sync` paths) — **not** live port or
sensor reads from the HTTP handler.

| Field | When present | Wire format (MQTT topic) |
|-------|----------------|--------------------------|
| `time_synced` | always | boolean |
| `local_time` | `time_synced` true | `YYYY-MM-DD HH:MM:SS` |
| `hopper` | always | `normal` / `low` / `empty` (`.../hopper`) |
| `dispense_busy` | always | boolean |
| `schedule_enabled` | always | boolean |
| `today_enabled` | always | boolean |
| `bowl_weight` | when publisher cache known | grams string or `""` unknown (`.../bowl_weight`) |
| `bowl_error` | when publisher cache known | boolean (`.../state`) |
| `battery` | when publisher cache known | `0`–`100` or `unknown` (`.../battery`) |
| `mains` | when publisher cache known | `ON` / `OFF` (`.../mains`) |
| `next` | when time synced and next slot exists | `{hour, min, g, in_min}` (`.../schedule/next`) |
| `display` | when display module ready | `{mode, brightness 0–4, battery_off_s, mains_off_s}` (`.../display`) |
| `power` | always | `{battery_wifi}` (`.../power`) |
| `portion` | always | `{g, status}` (`.../feed/portion`) |
| `scale` | always | `calibrated` / `zero_only` / `uncalibrated` |
| `network` | always | `{ssid, mqtt_host, mqtt_port, mqtt_user, ntp, password}` — `password` is a boolean (web password set); no secret is ever returned |
| `rssi` | after the first RSSI read | dBm integer (`.../wifi_rssi`) |
| `fw` | always | firmware version string (`git describe`) |
| `dispense_g` | always | Dispense-button amount in grams, `0` = one portion (`.../feed/dispense_amount`) |
| `progress` | always | `{state, portions, of, g}` (`.../dispense/progress`) |
| `ota_base` | when set | firmware base URL (`.../ota/base`) |
| `child_lock` | always | boolean |
| `eaten_today` | always | grams, one decimal (`.../eaten_today`) |
| `hopper_ir` | always | `-1` none yet, `0` beam clear, `1` blocked (`.../hopper_ir`) |

Per-topic GET mirrors (`/api/bowl_weight`, `/api/hopper`, …) are **deferred**
past v0.

POST body is the exact MQTT command payload for the equivalent topic.

| Method | Path | MQTT equivalent |
|--------|------|-----------------|
| POST | `/api/schedule/set` | `cmd/schedule/set` |
| POST | `/api/schedule/delete` | `cmd/schedule/delete` |
| POST | `/api/schedule/toggle` | `cmd/schedule/toggle` |
| POST | `/api/schedule/skip` | `cmd/schedule/skip` |
| POST | `/api/schedule/enable` | `cmd/schedule/enable` |
| POST | `/api/schedule/today` | `cmd/schedule/today` |
| POST | `/api/dispense` | `cmd/dispense` |
| POST | `/api/dispense/cancel` | `cmd/dispense/cancel` (no-op success when idle) |
| POST | `/api/feed/mode` | `cmd/feed/mode` plain body |
| POST | `/api/feed/overfill` | `cmd/feed/overfill` JSON body |
| POST | `/api/config` | `cmd/config` time slice (`tz_rule`, `tz_label`) |
| POST | `/api/display` | `cmd/display` (`mode` weight\|eaten_today, `brightness` 0–4 with 0 = panel off, `battery_off_s`) |
| POST | `/api/child_lock` | `cmd/child_lock` plain `ON` / `OFF` |
| POST | `/api/calibrate` | `cmd/calibrate` `{"action":"zero"\|"span"}` |
| POST | `/api/eaten_reset` | `cmd/eaten_reset` |
| POST | `/api/reboot` | `cmd/reboot` |
| POST | `/api/power` | `cmd/power` `{"battery_wifi":…}` |

| POST | `/api/ota_base` | `cmd/ota_base` plain-text URL |

suspended while the download runs, so a page could not show progress).

### Command routing

HTTP write handlers call the same `app_cmd_dispatch()` entry point as MQTT
(after topic classification). Schedule mutations go through `schedule_cmd.c`
shared with UART CLI and MQTT. UART CLI keeps human text output; HTTP and MQTT
use JSON.

### Administration

Web-only routes (no MQTT equivalent). Bodies are JSON; every field is optional
unless stated.

| Method | Path | Body | Effect |
|--------|------|------|--------|
| POST | `/api/network` | `{ssid, wifi_pass, mqtt_host, mqtt_port, mqtt_user, mqtt_pass, ntp}` | Validates every field first (same limits as provisioning; host names are letters, digits, `.` and `-`), then stores them. An NTP-only change applies at the next sync without reboot; any other change reboots. |
| POST | `/api/password` | `{"password":"…"}` | Sets the web password (4–32 characters); `""` removes it |
| POST | `/api/reprovision` | `{}` | Erases the Wi-Fi credentials and reboots into the setup access point |
| POST | `/api/factory_reset` | `{}` | Erases all application settings (Wi-Fi, MQTT, schedule, calibration) and reboots into setup |
| POST | `/api/import` | export JSON | Restores the settings of a `/api/export` backup |
| POST | `/api/unlock` | `{}` | Checks the `key=` line only: `{"ok":true}` when it matches (or no password is set), else `unauthorized`. Changes nothing |

**Wi-Fi change fallback.** A new SSID/password from `/api/network` is stored as
a trial (`wifi/ssid_new`, `wifi/pass_new`). After reboot the station tries the
trial first: on success it becomes the stored network; on failure the trial is
erased and the previous network is used (`[wifi] new network failed: back to
the previous one`).

**Export.** `/api/export` returns the feed, display, power, time, overfill and
portion settings plus the schedule. It never contains the Wi-Fi password,
MQTT password or web password; `/api/import` leaves those untouched.

## Security

Without a web password the panel is open on the LAN (same control surface as
MQTT). When a password is set (`system/web_pass`) every `/api/*` route needs it:

- A request authenticates with a body whose first line is `key=<password>`
  followed by `\n` and the normal body (possibly empty).
- **Reads** are then sent as POST to the read path (`POST /api/status` with
  body `key=…\n`). A POST whose body is empty after the key line is a read
  when the path has a GET route (`/api/feed/mode`, `/api/feed/overfill` and
  `/api/config` are both read and write paths); any other POST is a write.
- A plain `GET /api/status` returns only `{"locked":true}`; every other plain
  GET returns `{"ok":false,"error":"unauthorized"}`.
- A missing or wrong key returns `{"ok":false,"error":"unauthorized"}` after a
  `[tune]` 1 s delay (slows password guessing) and logs
  `[web] <path> rejected (unauthorized)`.
- `/` (the static page) stays open: it holds no data.

The remote telnet console asks for the same password
([uart-console.md](uart-console.md) § Security). Compile-time
`WEB_UI_ENABLE=n` removes the panel.
